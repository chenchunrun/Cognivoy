# Governance

Cognivoy currently follows a maintainer-led governance model.

## Maintainer

The project maintainer is [@chenchunrun](https://github.com/chenchunrun). The
maintainer is responsible for release decisions, repository administration,
security coordination, roadmap prioritization, and final merge decisions.

## Decisions

Routine decisions are made through issues and pull-request review. Material
changes to public APIs, persistent data formats, security boundaries, licensing,
or project governance should begin with an issue and allow reasonable time for
community feedback. The maintainer records the outcome in the issue or pull
request.

## Becoming a maintainer

Regular contributors may be invited to maintain the project after demonstrating
sustained, constructive participation; sound technical and security judgment;
respect for the Code of Conduct; and reliable review or release work. Access is
granted with the least privilege needed and may be removed after prolonged
inactivity, misuse, or a Code of Conduct violation.

## Project continuity

If the current maintainer can no longer maintain Cognivoy, repository control
should be transferred to an established contributor who agrees to preserve the
project's license, attribution, security policy, and public history.
